# 🚀 部署前安全检查清单

## ✅ 必须完成的检查项

### 1. 环境变量配置
- [ ] 复制 `.env.example` 到 `.env`
- [ ] 配置 `SESSION_SECRET`（至少32字符）
  ```bash
  # 生成强密钥
  openssl rand -base64 32
  ```
- [ ] 配置 `DATABASE_URL`
- [ ] 配置 `WEAVER_OA_URL` 和相关OA参数
- [ ] 如果需要CORS限制，配置 `ALLOWED_ORIGINS`

### 2. 数据库检查
- [ ] 数据库连接测试通过
- [ ] 所有表已创建（运行一次即可自动创建）
- [ ] 检查 SQL Server 链接服务器配置正确

### 3. 安全验证
- [ ] `SESSION_SECRET` 不是默认值
- [ ] `.env` 文件不在git仓库中（已在.gitignore）
- [ ] 生产环境不使用开发模式密钥
- [ ] HTTPS已启用（生产环境）

### 4. 功能测试
- [ ] 登录功能正常
- [ ] 创建会议功能正常

- [ ] 行动项分派功能正常
- [ ] OA推送功能正常（如已配置）

### 5. 性能检查
- [ ] 数据库连接池配置合理
- [ ] 文件上传目录有足够空间
- [ ] 日志级别适当（生产环境建议 warn/error）

## 🛠️ 常见问题排查

### 问题1：SESSION_SECRET错误
**症状：** 服务启动失败，提示 SESSION_SECRET required  
**解决：** 在 `.env` 中配置至少32字符的密钥

### 问题2：数据库连接失败
**症状：** API返回500错误，日志显示连接超时  
**解决：** 
1. 检查 `DATABASE_URL` 格式
2. 验证数据库服务运行中
3. 检查防火墙规则

### 问题3：文件上传失败
**症状：** 上传返回500错误  
**解决：**
1. 检查 `UPLOAD_DIR` 目录存在
2. 验证目录写权限
3. 检查磁盘空间

### 问题4：CORS错误
**症状：** 浏览器console显示CORS错误  
**解决：**
1. 配置 `ALLOWED_ORIGINS` 包含前端域名
2. 确保包含协议（https://）
3. 检查端口号是否匹配
