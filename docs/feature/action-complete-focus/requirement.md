# 行动项完成通知「聚焦显示」需求文档

> 版本：v1.0
> 创建：2026-09-20
> 状态：待实施
> 关联代码：`src/lib/wecom-action-push.ts`、`src/app/api/actions/[id]/route.ts`、`src/middleware.ts`、`src/app/tracking/page.tsx`

---

## 一、背景

责任人把行动项标记为「已完成」时，系统会给**提出人**发一张企业微信卡片：

```
✅ 你提出的行动项已完成
「确认物料打样及时性统计表上线时间」
责任人：陈巧霞 · 截止 2026-09-20
完成说明：沟通需求且已开发完成
```

卡片链接为 `.../tracking?shared=true&focusId=<actionId>`，意图是"打开行动项台账、只显示这一条"。

**实际现象**：提出人（如虞周峰）点进去经常是**空白页**（"行动项完成情况（0条）"），看不到完成情况。

---

## 二、现状与根因

### 2.1 链路

| 环节 | 位置 | 说明 |
|------|------|------|
| 触发通知 | `src/app/api/actions/[id]/route.ts:311-324` | `body.status === 'done' && existing.status !== 'done'` 时异步调用 |
| 生成卡片 | `src/lib/wecom-action-push.ts:117-170` | 收件人=提出人；链接 `156` 行 `/tracking?shared=true&focusId=<id>` |
| 免密进入 | `src/middleware.ts:88-138` | `/tracking` + `shared=true` 走企微 OAuth，保留 query |
| 台账页 | `src/app/tracking/page.tsx` | 拉 `/api/actions` 后前端过滤 |

### 2.2 根因

1. **`focusId` 只是一层附加过滤，不是"强制只显示这一条"**
   `tracking/page.tsx:549`：
   ```ts
   if (focusId && i.id !== focusId && (i as any).dbId !== focusId) return false;
   ```
   它是在**其它所有筛选之后/之中**再筛一次，压不住前面的条件。

2. **页面默认带一个"最近 30 天"的隐式日期窗口，且一直生效**
   - 默认值：`tracking/page.tsx:252-259`（`customDateStart = 今天-30`，`customDateEnd = 今天`）
   - 强制执行：`tracking/page.tsx:621-623`
   ```ts
   if (customDateStart && i.meeting_date && new Date(i.meeting_date) < new Date(customDateStart)) return false;
   if (customDateEnd   && i.meeting_date && new Date(i.meeting_date) > new Date(customDateEnd))   return false;
   ```
   该窗口在 UI 上并不显眼，用户很容易"不知道为什么少了记录"。

3. **持续项被无条件剔除**：`tracking/page.tsx:547` `if (i.due_date_type === 'continuous') return false;`（持续项完成卡片也会空，见问题2方案配套）。

### 2.3 实测样例

| 事项 | 会议 | 会议日期 | 点击时结果 |
|------|------|----------|-----------|
| 确认物料打样及时性统计表上线时间 | 2026年8月10日 7月份经营会议 | 2026-08-10 | 距点击 >30 天 → **被日期窗口剔除 → 空白** |
| 制定新产品试产延期问题改善方案 | 2026年9月10日 8月经营会议 | 2026-09-10 | 30 天内 → 按代码应可见 |

## 三、目标

1. 从完成通知卡片进入，**必然**能看到聚焦的那一条及其完成说明，不受默认筛选影响。
2. 台账默认不再"悄悄"隐藏较早会议的记录（或至少让日期范围可见、可清除）。
3. 不破坏现有筛选、排序、权限与各角色视图。

---

## 四、功能范围

### 含

- **聚焦短路**：`focusId` 存在时，只保留该条，绕过所有其它筛选（含 30 天窗口）。
- **日期范围调整**：默认改为「全部」，或把当前范围做成页面显著、可一键清除的筛选条。
- **（可选）完成详情卡**：聚焦态顶部直接展示"完成详情"（事项/责任人/提出人/截止/完成说明/完成时间/附件），不依赖台账行。
- **（配套）持续项完成不再发"已完成"卡片**：见 `audit-auto-detect` 方案第 6 条。

### 不含

- 不新增后端接口（`/api/actions` 已含所需字段）。
- 不改企微/IM/OA 推送通道本身。
- 不改 `/api/actions` 的服务端权限过滤逻辑（防越权靠它）。

---

## 五、交互需求

1. 带 `focusId` 打开 `/tracking`：
   - 顶部保留提示条「✅ 行动项完成情况（1条）」+「查看全部台账」。
   - 表格仅展示该条，且能看到「OA回传内容」列（完成说明）。
   - 若该条已不可见（被删除/取消/无权），显示空态而不是报错。
2. 点「查看全部台账」：清除 focusId，恢复默认视图。
3. 无 `focusId`：行为与现在一致（仅日期默认值按方案调整）。

---

## 六、权限

- 聚焦短路**仅作用于 `/api/actions` 已返回、当前用户本就可见的 items**，不绕过服务端权限（提出人/责任人可见，其它人仍不可见）。
- `/tracking` 继续受 middleware session 校验与角色过滤约束。

---

## 七、非功能需求

- 不在渲染期读取 `window`；`focusId` 仍走 `useEffect`（避免 hydration 不一致）。
- 大台账（数百条）聚焦时的过滤性能不劣化。

---

## 八、验收标准

- [ ] 完成通知卡片点入，聚焦条一定显示（含会议日期 >30 天的旧项）。
- [ ] 聚焦条能看到完成说明（OA回传内容）。
- [ ] 「查看全部台账」可恢复正常列表。
- [ ] 默认日期窗口不再无提示地隐藏旧记录（或范围可见可清除）。
- [ ] 非提出人/非责任人点入仍受权限限制，不越权看到他人事项。
- [ ] 无 focusId 时台账行为与回归前一致。
