# 会议看板「已完成项」详情查看 需求方案

> 版本：v1.0  ·  状态：已实现（2026-09-03）
> 创建：2026-09-03
> 涉及看板：周例会 `/weekly-board`、月度（公司月会）`/monthly-board`、产销会 `/production-board`

---

## 1. 背景

三块会议看板第 1 页「未完成项通报」里都有（或应有）「✓ 已完成项」分区，老板投屏时只能看到任务标题/责任人/部门/节点，**看不到这条任务当时"完成得怎么样"**——完成情况说明、证明附件都要切去别的页面翻，投屏汇报不通畅。

现状根因（代码层）：三块看板内部把 `/api/actions` 已返回的字段丢弃了——
- 页面内 `BoardItem` 接口只留 13 个演示字段（`weekly-board/page.tsx:19-34`、`monthly-board`、`production-board` 同款）；
- `completion_note / oa_result / oa_attachments / completed_at / completed_by / oa_score / evidence_files` 后端 `GET /api/actions` 已在返回（`api/actions/route.ts:211-255`），但看板不渲染；
- 已完成行 `Row` 无任何点击事件（`weekly-board/page.tsx:359-372`、`monthly` 354-367、`production` 350-363）。

→ 不需要新接口，数据已在手，补交互与展示即可。

## 2. 目标

点击看板「✓ 已完成项」的任意一行 → 弹出**任务完成详情**：任务基本信息 + 完成情况说明 + 证明附件（图片内嵌预览、其他文件打开/下载）。三块看板能力一致。

## 3. 用户故事

| 角色 | 诉求 |
|------|------|
| 老板（投屏） | 汇报会指到一条已完成项，直接看到"谁、何时、完成的什么、说明怎么写的、有没有证据"，不切页 |
| 管理者/秘书 | 快速核验某条已完成任务的完成质量与附件，做口头点评 |

## 4. 范围

### 4.1 纳入

| 项 | 说明 |
|----|------|
| 已完成行动项明细 | 周例会、产销会看板已有的「✓ 已完成项」分区行改为可点击；**月度看板当前没有该分区，需新增**「✓ 已完成项」分区（口径与其"未完成通报"同期），并对齐可点击 |
| 详情弹窗内容 | 任务信息（内容全文/部门/责任人/提出人/节点/完成时间）+ 完成情况说明 + 附件预览/下载 + 稽核分徽标 |
| 附件打开 | 本地上传附件（`/api/files/...`）图片内嵌预览+放大+下载；pdf/office/其他可打开下载 |

### 4.2 不纳入（本期明确不做）

- **持续项填报行**不点开：持续项「本期填报」仅看板文字列，不在已完成明细范围；`hyzs_continuous_progress` 无附件列，历史周期附件已被覆盖，不做追溯（已确认）。
- **OA 原始附件（token/docid）**：OA 回传已停用、后续均为本地上传；历史 OA token 附件看板不做抓取。`/api/continuous/attachment`（仅 admin）保持现状不动。
- **历史填报时间线**、按周期存附件（改表）均不做。
- 行动项「打X项」「未处理项」不做弹窗（本期只做已完成）。
- GSMALT（绩效面谈 V/X）看板明细按既定口径不做。

## 5. 交互设计

### 5.1 入口

- 「✓ 已完成项」分区行：整行可点，`cursor-pointer` + hover 高亮（沿用现有 hover 底色）+ 行尾加"查看"角标。
- 点击不干扰现有外壳交互：自动播放/翻页/沉浸(F) 期间点击正常；详情浮层层级高于沉浸层（现有沉浸 `z-[200]`，浮层需 `z-[400]+`），关闭/点遮罩后回到看板。

### 5.2 详情弹窗（示例版式）

```
任务完成详情
┌────────────────────────────────────────────┐
│ 任务内容：<description 全文，可换行>          │
│ 责任人：张三 · 开发部      提出人：李四       │
│ 原节点：2026-08-28    完成于：2026-08-28 14:20│
│ 稽核分：[V/ X/ 0 / —]                        │
│────────────────────────────────────────────│
│ 完成情况说明                                  │
│ <清洗后文本；空则显示"（无说明）">              │
│────────────────────────────────────────────│
│ 证明附件（n）                                 │
│ [缩略图] [缩略图]     点击放大 / 下载          │
│ [文件.pdf] [文件.docx]  打开 / 下载            │
│ （无附件时显示"（无附件）"）                     │
└────────────────────────────────────────────┘
```

- 说明文本展示前必须清洗导入元数据（套用 `src/lib/oa-result-display.ts` 的 `getDisplayOaResult/stripEmbeddedMetaJson`），防止把 `{"y":..,"w":..,"d":..}` 当正文。

## 6. 字段口径

### 6.1 已完成判定（与现有各板一致）

| 看板 | 已完成判定 | 现有实现锚点 |
|------|-----------|--------------|
| 周例会 | 本期（上周）到期 & `isDone(i)`（`oa_score===1` 或 `status==='done'`；打 0 不算） | `weekly-board/page.tsx:863-877` |
| 产销会 | 本期（上月16~本月15）到期 & `isDone(i)` | `production-board/page.tsx:850-865` |
| 月度 | **新增**：按月度看板既有"未完成通报"同期口径取已完成（`done`）集合 | monthly 需新写，参照另两板 |

> 超期无回传自动判 X（`effectiveScore`）逻辑保留，不进已完成区，不影响本需求。

### 6.2 详情展示字段（数据已由 `GET /api/actions` 返回，无需新接口）

| 字段 | 来源 | 展示 |
|------|------|------|
| description | `/api/actions` | 正文全文 |
| owner / dept | `/api/actions` | 责任人/部门 |
| proposer | `/api/actions` | 提出人 |
| due_date | `/api/actions` | 原节点 |
| completed_at / completed_by | `/api/actions` | 完成时间/完成人（空则"—"） |
| oa_score | `/api/actions` | 徽标：1=V、-1=X、0=0、空/未稽核=—（徽标仅作展示，不改稽核） |
| **完成情况说明** | `completion_note` 或清洗后的 `oa_result` | 主显=清洗后 `oa_result`（系统填报主路径）；为空再取 `completion_note`；都空显示"（无说明）" |
| **附件** | `oa_attachments`（URL 数组） | 见 7 |

### 6.3 附件处理（本期仅本地上传）

| 附件形态 | 处理 |
|----------|------|
| `/api/files/...`（图片 jpg/png/gif/webp） | 内嵌缩略图，点击放大预览（复用现有轻量大图弹窗样式），附下载/新窗口打开 |
| `/api/files/...`（pdf/office/其他） | 列表项：图标+文件名，点击新窗口打开（`GET /api/files/[id]` 已按 MIME 输出），提供下载 |
| OA 原始 token / docid（历史遗留） | 显示"（历史OA附件，暂不支持预览）"，置灰不可点 |
| `evidence_files`（纯文件名，如拖拽完成写入） | 仅当 `oa_attachments` 为空时以文件名只读列出，标注"（仅文件名，无文件可预览）" |

## 7. 权限与安全

- 看板角色门槛维持现状（admin/manager/secretary 可见看板）。
- 附件直开复用 `GET /api/files/[id]`（现状无额外登录校验，沿用，不新增暴露面）；**不引入** `/api/continuous/attachment`（admin-only）到看板，规避权限不匹配。
- 展示前对文本做长度/换行控制；附件文件名/URL 仅按 `/api/files/` 前缀白名单判定可开，其余一律置灰，防注入与越权跳转。

## 9. 非功能与回归

- 数据本地已有，打开详情零额外请求；附件按需懒加载图片。
- 回归清单：三块看板翻页/自动播放/沉浸(F)/周期偏移、点遮罩关闭、图片放大、PDF/Office 打开；数据为空的旧任务不报错（占位符兜底）。
- 同一份改动三处页面，避免破坏各自周期的筛选口径（尤其月度新增区必须与既有"未完成通报"同期逻辑一致）。

## 10. 决策记录

| # | 决策 | 结论 |
|---|------|------|
| 1 | 范围 | 仅行动项「已完成」；持续项填报行、打X/未处理行不做 |
| 2 | OA 附件 | 不做抓取，看板仅支持 `/api/files` 本地附件（OA 已停用） |
| 3 | 月度看板 | 新增「✓ 已完成项」分区并对齐周/产销 |
| 4 | 完成说明口径 | `oa_result`(清洗) 主显 → `completion_note` 兜底 |
| 5 | 附件仅文件名 | `evidence_files` 纯文件名只读展示，不可开 |
| 6 | 弹窗内容 | 基本信息+完成说明+附件；不含历史时间线 |
| 7 | 稽核徽标 | 仅展示 V/X/0/—，不在此处做稽核操作 |
