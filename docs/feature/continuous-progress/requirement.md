# 持续项按会议节奏定期催办进度 需求方案

> 版本：v1.1  ·  状态：已实施迭代（2026-09-03 新增「无进展」填报）
> 关联代码：`lib/todo-push.ts`、`lib/chat-client.ts`、`src/server.ts`（定时调度）、`app/continuous/`、`app/task-confirm/`、`app/api/actions/`

---

## 〇、2026-09-03 迭代：持续项填报「无进展」免填优化

> 触发：部分持续项本周期确实无完成情况，原先强制必填"进展说明"并让附件可选，填报体验差且无法区分「无进展」与「有内容」。

### 目标

系统内填报持续项时先选择「本期是否有完成情况」：
- **无进展**：进展说明、图片附件一律免填（隐藏），一键提交。
- **有进展**：进展说明必填，且**图片附件至少 1 张必填**（规则收紧，防止无证据空填）。

### 交互（影响两处填报弹窗，逻辑一致）

| 页面 | 位置 |
|------|------|
| 我的任务 `/mytasks`（含管理员群体代填） | 持续项汇报弹窗 |
| 待办中心 `/kanban`（企微卡片直达） | 持续项汇报弹窗 |

- 选「无」→ 隐藏并忽略说明/附件；提交内容统一为文本 `无`，后台打 `is_none=1`。
- 选「有」→ 说明 + ≥1 张附件校验必填；`is_none=0`。
- 上期记录为「无」的任务重开弹窗时默认仍选「无」。

### 落库

`hyzs_continuous_progress` 新增列 **`is_none INT NULL`**（1=无进展，0/null=有内容，含 OA 文本填报）。

| 字段 | 说明 |
|------|------|
| progress | 无进展填规范文本 `无`；有内容填说明原文 |
| is_none | 1=无进展；0/NULL=有内容 |

### 统计口径（供后续）

- 填报表的"已填报"口径**不变**：无进展也视为已填报（负责人已回应）。
- 后续如需统计"无进展 vs 有进展"，按 `is_none` 分组即可；历史 OA 文本填报因 `is_none` 为空默认归入"有内容"，若需把 OA 填写的"无"文本纳入，可按 `progress='无'` 兜底识别。

### 边界与限制

- **仅覆盖系统内填报**；责任人在 OA 端（泛微表单）填写仍由 OA 表单自身约束，本优化不生效。
- 首页/台账/项目详情里的旧版弹窗不处理持续项，未改。
- 「无进展」提交会把该行动项的历史 `oa_attachments` 清空，避免旧附件被误读为本期进展证据。

### 影响面

- 修改：`continuous-progress-storage.ts`（加列+upsert 支持 is_none）、`api/actions/[id]/route.ts`（持续项分支打标）、`mytasks`、`kanban` 弹窗。
- 不影响：OA 推送/回拉、各看板"已填报"判定、非持续项流程、稽核 V/X/0。


**现状**：持续项（`due_date_type='continuous'`，来源周例会/月度总结会/产销协调会等）在系统里**只有"稽核 V/X/0"**，没有"定期让责任人汇报进展"的能力。

**业务痛点**：
1. 周会产生的持续项，**每周一开会**才看进展，中间一周责任人有没有在推进、卡在哪，管理端不知道。
2. 责任人不会主动来系统更新进度，需要**每周五早上被推着填一次**。
3. 月度会议、产销协调会各有自己的节奏，**需要按各自固定日子催办**。
4. 持续项的进展**不能和行动项（一次性的待办）混为一谈**——生命周期、催办节奏、回填方式都不同。

---

## 二、需求目标

按"**来源会议类型 → 固定催办节奏**"，自动把对应持续项**生成催办清单推送给责任人**，责任人填写进展后回填系统，形成：
```
周会/月度会/产销会 开会产出持续项
        ↓
固定日（如周五早上）自动生成该会议类型全部持续项的催办清单
        ↓
推送给各责任人（IM 消息，含点击回填链接）
        ↓
责任人逐项填进展（进展中/已完成/有阻碍 + 说明）
        ↓
回填系统，持续项展示最新进展 + 历史进展时间线；管理端可见
```

---

## 三、功能范围

### 3.1 纳入范围

| 模块 | 内容 |
|------|------|
| 节奏配置 | 会议类型 → 催办规则（频率：每周/每月；触发星期几/每月几号；触发时间；是否启用） |
| 自动生成 | 到点扫描该会议类型的全部持续项，按责任人聚合生成「本期待填清单」 |
| 推送 | 复用 IM 推送，给每位责任人发本期持续项清单 + 回填链接；幂等防重复 |
| 进展回填 | 责任人点链接进回填页，逐项填：进展说明 + 状态（进行中/已完成/有阻碍）；已完成的持续项退出后续催办 |
| 历史沉淀 | 每次回填形成一条进展记录（谁/何时/说了什么/状态），持续项展示时间线 |
| 管理视图 | 持续项页显示"最新进展/上次回填时间/是否有阻碍"，支持筛选"本期未回填" |

### 3.2 不纳入范围（本期）

- 不改变持续项本身的增删改与稽核能力（V/X/0 保留，但回填是主流程）。
- 不做责任人超时未填的升级告警（二期可加"连续 N 期未填"提醒）。
- 不做审批流（回填内容是否需要领导确认，二期评估）。

## 四、核心流程与数据模型

### 4.1 数据模型

#### 表 `hyzs_cadence_config`（催办节奏配置）

| 字段 | 说明 |
|------|------|
| id | 主键 |
| meeting_type | 会议类型：周例会 / 月度总结会 / 产销协调会 / 公司月会 ... |
| cadence | 'weekly' / 'monthly' |
| trigger_day | weekly→星期几（1-7，周五=5）；monthly→每月几号 |
| trigger_time | HH:mm（如 09:00） |
| enabled | 是否启用 |
| updated_at | 更新时间 |

#### 表 `hyzs_continuous_progress`（持续项进展记录）

| 字段 | 说明 |
|------|------|
| id | 主键 |
| action_id | 持续项 ID（FK hyzs_action_items.id） |
| cycle_key | 催办周期标识（如 `周例会-2026-W32` / `月度总结会-2026-07`），用于幂等 |
| progress | 进展说明文本 |
| status | 'in_progress' / 'done' / 'blocked' |
| filled_by | 填写人（OA 登录名） |
| filled_at | 填写时间 |
| created_at | 记录时间 |

索引：`(action_id, cycle_key)` 唯一，保证每期每项只一条。

#### 持续项上扩展（hyzs_action_items 加列，可选）

- `last_progress_at`：最近一次回填时间（展示用，可从 progress 表取，亦可冗余）。
- 状态若 `done` 则不再进入后续催办。

### 4.2 生成与推送流程

```
server.ts 定时器（每分钟 tick）
  → 命中某条 cadence（trigger_day/time）
  → 计算本期 cycle_key（周 N / 月 M）
  → 扫描：该 meeting_type 的持续项（source_text=该类型, due_date_type='continuous', status != 'done'）
  → 按 owner 聚合
  → 幂等检查：该 cycle_key + action_id 是否已推/已填（hyzs_continuous_progress 有记录则跳过）
  → 逐个责任人推送 IM 消息（复用 batchSendOAUserMessage）
     内容：本期待填持续项清单 + 「点击回填进展」链接（含 cycle_key）
```

### 4.3 回填页面（复用 task-confirm 思路）

- 责任人点消息链接 → 进入 `/task-confirm/:key` 或 `/continuous-fill/:cycleKey`（**不登录也可，凭 token 直达**，或要求登录）。
- 页面列出本人本期持续项，每项：提议内容 + 最近进展 + 输入框（进展说明）+ 状态单选（进行中/已完成/有阻碍）。
- 提交 → 写 `hyzs_continuous_progress`；若选「已完成」则把持续项状态置 done。
- 提交后展示"已提交，感谢"。

### 4.4 管理端视图（持续项页增强）

- 持续项表格增加列：**最新进展**、**上次回填时间**、**状态（进行中/已完成/有阻碍）**、**本期是否已回填**。
- 新增筛选：按会议类型、按"本期未回填"、按有无阻碍。
- 点开持续项可看**历史进展时间线**（谁在什么时候填了什么）。

## 五、方案选项与推荐

| 方案 | 做法 | 成本 | 特点 |
|------|------|------|------|
| **方案A：复用 TodoPush 基建 + 进展表** ⭐推荐 | 仿照 `todo-push.ts` 新写 `continuous-push.ts`；新增两张表；回填页复用 task-confirm 模式；server.ts 加一个调度 | 中 | 改动集中、可独立上线、不碰行动项 |
| 方案B：不做定时，改为管理端手动"生成本期清单并推送" | 无定时器，管理员在持续项页点"催办"按钮 | 低 | 灵活但依赖人工记得点 |
| 方案C：完整"持续项看板 + 周期快照 + 报表" | 在 A 基础上加看板/报表/超期升级 | 高 | 二期演进目标 |

**推荐**：先做 **方案B（手动催办按钮）+ 方案A（自动定时）分期**——一期先支持管理端一键"按会议类型生成并推送本期持续项"，跑通回填闭环；二期加 server.ts 定时自动触发。

## 六、入口与权限

| 入口 | 说明 |
|------|------|
| 持续项页「催办」按钮 | admin/manager 可手动触发某会议类型的本期催办（方案B） |
| 自动定时 | server.ts 按 cadence 配置自动触发（方案A，二期） |
| 回填链接 | 责任人凭消息链接进入，无需管理员权限 |
| 节奏配置页 | admin 维护 `hyzs_cadence_config`（可并入基础设置页） |

---

## 七、非功能需求

- **幂等**：同 `cycle_key` 每项只推一次、只填一条（唯一索引兜底）。
- **性能**：扫描与聚合按类型过滤，一次催办 <2s；推送失败不阻塞其他责任人。
- **可靠**：推送失败记录日志，可手动重推；回填写入失败不丢用户输入（提示重试）。
- **独立**：全程不写 `hyzs_action_items` 的待办/稽核主流程，仅回填"已完成"时改状态；不进入行动项台账与待办。

---

## 八、分期建议

| 期 | 内容 | 目标 |
|----|------|------|
| 一期 | 两张表 + 管理端"按会议类型手动催办"按钮 + 回填页 + 持续项页进展时间线 | 打通"生成→推送→填写→回填"闭环，先人工触发 |
| 二期 | cadence 配置 + server.ts 定时自动催办 + 幂等 | 周会每周五早上、月度会每月固定日自动推 |
| 三期 | 超期未填升级提醒、进展报表/看板、按类型导出 | 管理与报表增强 |

## 九、验收标准

- [ ] 能配置"周例会：每周五 09:00"的催办节奏。
- [ ] 手动（一期）或定时（二期）触发后，该类型全部未完成持续项按责任人生成清单。
- [ ] 责任人收到 IM 消息，含回填链接；点开能逐项填进展并选择状态。
- [ ] 回填后持续项页显示最新进展、上次回填时间、历史时间线。
- [ ] 同一周期重复触发不重复推送/重复记录。
- [ ] 标记「已完成」的持续项不再进入后续催办。
- [ ] 全程不影响行动项台账/待办数据。
