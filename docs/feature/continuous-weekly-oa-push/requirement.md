# 周例会持续项每周打包推送 OA 需求文档

> 版本：v3.1  ·  状态：待评审
> 涉及：持续项（`due_date_type='continuous'`）、OA 任务推送（`uf_meetingplan`）、OA 回传同步、企业微信 IM 提醒、**前台可配置的定时调度**
> 关联代码：`lib/oa-task-push.ts`、`lib/chat-client.ts`、`src/server.ts`、`api/oa/pull-results/`、`app/settings/`

---

## 一、背景与问题

持续项（如"零星采购的标准执行""物料打样及时率汇报"等）是各类会议中长期跟进的事项，**没有明确的截止节点**，责任人不会主动更新进展，管理端也不清楚每周推进情况。

**期望**：像**行动项**一样，让持续项在 OA 里生成带**节点**的任务，按各会议的节奏自动打包推送 + 企业微信提醒，责任人在 OA 回填后系统自动同步归集。

---

## 二、核心挑战

### 2.1 多类型、多节奏

不同会议类型有不同的调度节奏：

| 会议类型 | 推送节奏 | 典型场景 |
|----------|---------|---------|
| 周例会 | 每周五 09:00 | 每周五打包所有周例会持续项，推 OA + 企微 |
| 月度总结会 | 每月 25 日 09:00 | 每月 25 号打包月度持续项 |
| 产销协调会 | 每周二 09:00 | 每周二打包产销持续项 |
| 公司月会 | 每月 1 日 09:00 | 每月 1 号打包公司月会持续项 |

**这些节奏不能写死在代码里**，需要**前台管理页面可配**，随时增减。

### 2.2 同一持续项多次推送、多次回传的归集

持续项是长期跟进的，每次推送在 OA 生成一条新任务，责任人每次回填一次进展。**系统如何把历史回传组合起来形成进展时间线？**

#### 方案：进展快照表 `hyzs_continuous_progress`

每次 OA 回传同步回来时，**不直接覆盖持续项的 `oa_result`**，而是**追加一条进展记录**到专门的表（详见第四节）。

#### 周期日期不需要 OA 回传

推送 OA 时，周期日期（周五/25号等）已经**编码在 task_id 里**：

```
task_id = CONT_周例会_2026-08-04__ACT_xxx_2026-08-04
                              └─ 周期日期 ─┘
```

OA 回传时带回 `task_id`，系统从里面**解析出周期日期**，跟回填内容一起存进进展表：

```
cycle_date = 2026-08-04   ← 从 task_id 解析，不需要 OA 额外回传
progress   = "已联系3家供应商，完成40%"  ← OA 回传的 wcjgsm
oa_status  = 0             ← OA 回传的 status
```

所以统计时查进展表就能看到**每个持续项在什么时间做到什么程度**的完整记录。

#### 多周归集示例

持续项「零星采购标准执行」连续 3 周推送 + 回传：

| action_id | cycle_date | progress | oa_status |
|---|---|---|---|
| ACT_xxx | 2026-08-04 | 已联系3家供应商，完成40% | 0（待处理）|
| ACT_xxx | 2026-08-11 | 6家中完成5家，剩余1家下周交付 | 2（已处理）|
| ACT_xxx | 2026-08-18 | NULL（责任人未回填）| 0 |

每条独立保存，不互相覆盖。查 `WHERE action_id=ACT_xxx ORDER BY cycle_date` 即可展示完整时间线。

#### 持续项本体不动

- 持续项的 `due_date` **保持 NULL**（它是持续项，永远没有截止日）。
- 推送 OA 时 `due_date` 只作为**参数传给 OA**（让 OA 任务有节点），**不回写系统持续项**。
- 持续项的 `status`/`oa_score` 由人工稽核控制，OA 回传不改变。
- 持续项本体上仅冗余 `last_progress` + `last_progress_at`（最新进展摘要），方便快速展示，不用每次 JOIN 进展表。

## 三、前台调度配置页

### 3.1 页面位置

在**基础设置**（`/settings`）页新增一个「**持续项推送配置**」标签页。

### 3.2 配置项

每条配置对应一种会议类型：

| 字段 | 类型 | 示例 | 说明 |
|------|------|------|------|
| 会议类型 | 下拉（来自 `meeting-types`） | `周例会` | 匹配持续项的 `source_text` |
| 推送频率 | 单选 | `每周` / `每月` | weekly / monthly |
| 推送星期 | 下拉 1-7 | `周五` | weekly 时显示（1=周一..7=周日） |
| 推送日期 | 输入 1-28 | `25` | monthly 时显示（每月几号） |
| 推送时间 | 输入 HH:mm | `09:00` | 当天触发时间 |
| 是否启用 | 开关 | `开` / `关` | 关闭后不自动推 |
| 最后推送时间 | 只读 | `2026-08-04 09:00` | 上次自动推送的时间 |

### 3.3 操作

- **新增**：选会议类型 + 设频率/日期/时间 → 保存。
- **编辑**：修改频率/日期/时间 → 保存。
- **启用/关闭**：一键切换。
- **手动触发**：每条配置旁边一个「立即推送」按钮，验证用。
- **查看推送记录**：点「记录」展开最近 N 次推送日志。

### 3.4 示例配置

| 会议类型 | 频率 | 触发 | 时间 | 状态 |
|----------|------|------|------|------|
| 周例会 | 每周 | 周五 | 09:00 | ✅ 启用 |
| 月度总结会 | 每月 | 25 日 | 09:00 | ✅ 启用 |
| 产销协调会 | 每周 | 周二 | 09:00 | ✅ 启用 |
| 公司月会 | 每月 | 1 日 | 09:00 | ⬜ 关闭 |

## 四、数据模型

### 4.1 新表 `hyzs_cadence_config`（调度配置）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | NVARCHAR(64) PK | 主键 |
| meeting_type | NVARCHAR(32) | 会议类型（匹配 `source_text`） |
| cadence | NVARCHAR(10) | `weekly` / `monthly` |
| trigger_day | INT | weekly: 1-7（周一~周日）；monthly: 1-28 |
| trigger_time | NVARCHAR(5) | `HH:mm` |
| enabled | BIT | 1=启用, 0=关闭 |
| last_pushed_at | NVARCHAR(30) | 上次自动推送时间 |
| created_at | NVARCHAR(30) | |
| updated_at | NVARCHAR(30) | |

### 4.2 进展归集表 `hyzs_continuous_progress`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT IDENTITY PK | |
| action_id | NVARCHAR(64) | 持续项 ID |
| cycle_date | NVARCHAR(10) | 本周期节点日期 |
| oa_task_id | NVARCHAR(200) | OA 任务 task_id |
| progress | NVARCHAR(MAX) | 责任人回填内容 |
| oa_status | INT | OA 状态（0=待处理, 2=已处理） |
| synced_at | NVARCHAR(30) | 同步时间 |

唯一约束：`(oa_task_id)`。

### 4.3 持续项本体扩展

| 字段 | 说明 |
|------|------|
| `last_progress` NVARCHAR(MAX) | 最近一次回传（冗余，展示用） |
| `last_progress_at` NVARCHAR(30) | 最近一次回传时间 |

### 4.4 OA 侧区分

| 字段 | 行动项 | 持续项 |
|------|--------|--------|
| source_app | `HYZS` | `HYZS_CONT` |
| task_id 前缀 | 批次/会议 ID | `CONT_<会议类型>_<日期>` |
| meeting_title | 会议/批次名 | `<会议类型>持续项跟进（日期）` |

## 五、完整数据流

```
┌──────────────────────────────────────────────────────┐
│  server.ts 每分钟检查 hyzs_cadence_config             │
│  命中 → 取该 meeting_type 的未完成持续项               │
│  持续项 due_date 不动（保持 NULL）                     │
│  pushTasksToOA（source_app=HYZS_CONT，按周期唯一 ID）  │
│    └─ OA 任务 due_date=当天（只传 OA，不回写系统）     │
│  batchSendOAUserMessage（企微提醒，按责任人聚合）       │
│  logOperation（操作日志）                              │
└──────────────────┬───────────────────────────────────┘
                   ↓
┌──────────────────────────────────────────────────────┐
│  责任人在 OA 回填                                      │
│  uf_meetingplan.wcjgsm = 进展内容                     │
│  uf_meetingplan.status = 2                            │
└──────────────────┬───────────────────────────────────┘
                   ↓
┌──────────────────────────────────────────────────────┐
│  pull-results 定时同步                                │
│  扫描 source_app='HYZS_CONT'                          │
│  解析 task_id → action_id + cycle_date                │
│  写入 hyzs_continuous_progress（追加，不覆盖）         │
│  更新持续项 last_progress / last_progress_at           │
│  持续项 status 不变（人工稽核控制）                    │
└──────────────────────────────────────────────────────┘
```

## 六、入口与权限

| 入口 | 说明 |
|------|------|
| **配置页** `/settings` →「持续项推送配置」标签 | admin 可增删改配置 |
| 自动调度 | `server.ts` 每分钟检查 `hyzs_cadence_config` |
| 手动触发 | 配置页每条旁边「立即推送」按钮（admin） |
| OA 回传同步 | `pull-results` 定时自动执行 |
| 持续项页 | 显示最新进展 + 上次回填 + 历史时间线 |
| 操作日志 | `/logs` 可见推送 + 同步记录 |

## 七、非功能需求

- **幂等**：同周期重复推送 → OA 同 task_id 更新不新增；同一回传重复同步 → `(oa_task_id)` 唯一约束兜底。
- **可靠**：单条失败不影响其他；配置关闭后不推送。
- **性能**：每分钟检查配置表（极轻）；推送 N 条持续项 ≤ 60s。
- **扩展**：新增会议类型只需在配置页加一条，不改代码。
- **区分**：OA `source_app=HYZS_CONT` 与行动项 `HYZS` 隔离。
