# 会议编辑稳定性与归档数据一致性修复 测试文档

> 版本：v1.0  ·  状态：待执行（自动化冒烟已通过，以下为手工用例）
> 需求文档：`requirement.md` ｜ 开发文档：`development.md`
> 环境：dev（http://localhost:5000），需具备会议创建/编辑权限的账号

---

## 一、测试范围

会议详情页行动项行内编辑、新增/复制/删除；纪要/摘要保存与派生；归档/解档后数据完整性；接口幂等与并发冲突。

## 二、前置条件

1. dev server 运行中（`pnpm dev`，端口 5000）。
2. 测试账号为会议参会人或主持人（否则详情页 403）。
3. 已自动执行并通过：`smoke-meeting-fix.mjs`（18 项接口级冒烟，见 development.md 第五节）。

## 三、测试用例表

| 编号 | 用例 | 前置 | 步骤 | 预期 | 优先级 |
|------|------|------|------|------|--------|
| TC01 | 新增行动项行内编辑不跳 | 会议详情页行动项 Tab | ① 点「新增」② 立即在描述框连续输入 20 字 ③ 失焦 ④ 再点日期控件改日期 | 全程光标不丢、行不闪烁、不滚动跳变；「已保存」角标出现 | P0 |
| TC02 | 新增后连续快速操作不撞 key | 同上 | 连续点「新增」「复制」各 3 次以上，逐个编辑保存 | 无 React key 告警；每行均可独立保存 | P0 |
| TC03 | 手动项保存纪要后不消失 | 已生成纪要并派生 ≥1 条 | ① 行动项 Tab 手动新增 1 条（填负责人+优先级=高）② 回纪要 Tab 改任意文字并保存 ③ 回行动项 Tab | 手动项仍在；负责人/优先级保持手填值 | P0 |
| TC04 | 摘要行内编辑不删行动项 | 同上 | 摘要 Tab 点击「会议概述」直接改字，失焦 | 保存成功；行动项数量无变化 | P0 |
| TC05 | 归档后内容完整 | 手动项+派生项共存 | 点「锁定版本（归档）」→ 确认 → 刷新页面 | 归档前后行动项数量一致；锁定态只读展示正常 | P0 |
| TC06 | 纪要表格删行联动规则 | 表格 3 行，其中 1 行从未在行动项 Tab 编辑过 | ① 保存纪要 ② 从表格删除该行再保存 | 该未编辑派生项消失（软取消，台账留痕）；编辑过的项不受影响 | P1 |
| TC07 | 表格删中间行手动字段不串行 | 表格 3 行；第 2 行在行动项 Tab 改过优先级=高 | 删除表格第 1 行 → 保存 | 剩余两行正确对应；第 2 行优先级仍为高 | P1 |
| TC08 | 保存失败可见提示 | 断开网络或停台账库 | 新增行动项并编辑字段 | 弹出失败提示；临时行保留；恢复后重试成功且无重复行 | P0 |
| TC09 | 并发保存冲突提示 | 两个浏览器登录不同参会人开同一会议 | A、B 同时进纪要 Markdown 编辑 → A 保存 → B 保存 | B 收到「他人已保存…是否覆盖」确认框；选否则 B 的编辑保留在本地（未保存栏仍在） | P1 |
| TC10 | 他人归档时退出编辑 | A 编辑纪要正文（Markdown 模式）| B 在另一端锁定版本 | A 的编辑模式自动退出；未保存内容不清空（dirty 守卫生效） | P2 |
| TC11 | Markdown 编辑不被外部重置 | A 编辑纪要正文中 | B 保存同一会议纪要 | A 的输入框内容不被覆盖、不退出编辑模式 | P0 |
| TC12 | 历史 JSON-only 项可见可编辑 | 管理员构造：台账无行、会议 JSON 有行（历史分歧数据） | 打开会议详情 → 编辑该项任意字段 | 项在列表可见；编辑保存成功（首次编辑自动回填台账）；刷新后仍在 | P1 |
| TC13 | 幂等：重复提交不重复 | 无 | 接口层：同 `addActionItem.id` 连发两次 PATCH | 台账仅 1 行（冒烟已覆盖，页面双击保存场景同理） | P1 |
| TC14 | 解档后行动项完整 | 已归档会议 | 解除归档 → 刷新 | 行动项与归档时一致；可继续编辑 | P1 |

## 四、回归清单

- [ ] 我的待办（`/mytasks`）：归档会议的行动项正常显示（锁定过滤规则未动）。
- [ ] 归档 OA 推送：锁定后 OA 推送结果提示与改动前一致（lock 路由未改）。
- [ ] 「我的任务」汇报进展 → 保存纪要 → 汇报内容（oa_result）不被派生覆盖（PRESERVE）。
- [ ] 看板/台账页（kanban/tracking）行动项显示与编辑正常（消费同一 API，id 口径兼容）。
- [ ] 批次导入（batch）行动项不受影响。
- [ ] 删除会议 → 台账行清理正常（DELETE 路径未改逻辑，仅 meetings/[id] DELETE 原样）。
