# 操作日志（操作审计）需求文档

> 版本：v1.0  ·  状态：待评审
> 涉及：行动项稽核、状态变更、批量导入、会议管理、OA 同步等关键操作的可追溯
> 关联代码：`api/actions/`、`api/meetings/`、`api/operations/`、`components/operation-log.tsx`、`storage/database/`、`lib/session.ts`

---

## 一、背景与问题

系统当前没有任何「谁在什么时间做了什么操作」的审计记录：

| 问题 | 现状 |
|------|------|
| 稽核误改无追溯 | V/X/0 被改后查不到是谁改的、改成什么 |
| 导入/删除不可审计 | 批量导入、删除、转派无操作记录 |
| 会议操作无留痕 | 创建、锁定、删除、导出纪要无法追溯 |
| 现有日志形同虚设 | `hyzs_operation_logs` 表**不存在**（库与 schema 均无），`/api/operations` 读日志必然报错，`OperationLog` 组件永远空白 |

**目标**：建立统一的操作审计能力，覆盖关键操作，管理员可查询「谁、何时、对什么、做了什么、改了什么」。

---

## 二、功能范围

### 2.1 纳入范围（本期）

| 模块 | 记录的操作 |
|------|-----------|
| 行动项 | 人工稽核 V/X/0（设置与清除）、状态变更（done/blocked/in_progress）、重新派发、删除、新增 |
| 批量导入 | Excel/CSV 导入批次创建（含条数）、批次推送 OA、批次删除 |
| 会议 | 创建、编辑、锁定/归档、解除归档、删除、生成/重新生成纪要、导出 |
| OA | 拉取完成结果同步（成功条数） |
| 系统 | 登录（可选，本期仅记录关键写操作） |

### 2.2 不纳入范围（本期）

- 纯查询/浏览行为（查看页面、导出 CSV 由前端本地触发的不记）。
- 企微/OA 侧的行为（只记录系统内动作）。
- 登录/登出审计（后续版本）。

---

## 三、用户故事

1. 作为**管理员**，我希望能按「操作人、操作类型、时间范围」筛选日志，以便排查"这个 V 是谁打错的"。
2. 作为**管理员**，我希望点开一条日志能看到**改动前后**（如 V→X），以便还原现场。
3. 作为**管理员**，我希望日志按时间倒序、分页展示，量大时不卡。
4. 作为**普通用户**，我希望**我自己**的敏感操作（稽核、删除、转派）也有记录可查（个人视角）。

## 四、数据模型

### 4.1 表 `hyzs_operation_logs`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT IDENTITY | 主键 |
| operator_login_id | NVARCHAR(64) | 操作人 OA 登录名 |
| operator_name | NVARCHAR(64) | 操作人姓名（冗余，便于展示） |
| action | NVARCHAR(32) | 动作类型：audit/status_change/reassign/delete/create/import/batch_push/meeting_create/meeting_update/meeting_lock/meeting_unlock/meeting_delete/export/oa_sync |
| target_type | NVARCHAR(32) | 对象类型：action_item / meeting / batch / import |
| target_id | NVARCHAR(64) | 对象 ID |
| summary | NVARCHAR(500) | 一句话描述（展示用） |
| detail | NVARCHAR(MAX) | JSON：{ before, after, changes } 等 |
| ip_address | NVARCHAR(45) | 客户端 IP（可选） |
| created_at | NVARCHAR(30) | ISO 时间 |

索引：`(created_at DESC)`、`(operator_login_id)`、`(action)`、`(target_id)`。

## 五、交互需求

### 5.1 日志查询页 `/logs`

- 仅 **admin** 可见（侧边栏入口）。
- 顶部筛选：操作人（下拉，来自组织架构）、动作类型（下拉）、时间范围（近7天/近30天/自定义起止）。
- 列表：时间 / 操作人 / 动作 / 对象 / 摘要，倒序分页（每页 20）。
- 行展开可看 detail 的 JSON（前后对比）。
- 空态：「暂无操作记录」。

### 5.2 会议详情页操作时间线（复用现有 `OperationLog`）

- 会议「日志」页签显示该会议相关操作（含行动项稽核如果挂到该会议）。

---

## 六、入口与权限

| 入口 | 权限 |
|------|------|
| `/logs` 日志查询 | 仅 admin |
| 会议详情日志页签 | 有会议查看权限者 |
| 写入日志 | 任意已登录用户触发的写操作（由后端统一记录） |

---

## 七、非功能需求

- **性能**：写日志为异步/非阻塞，不拖慢主流程；读日志分页 ≤200ms（热）。
- **可靠**：日志写入失败不影响主操作（try/catch 吞掉并 console.warn）。
- **一致性**：操作记录在业务提交成功后写入。
- **安全**：detail 不记录明文密钥；IP 仅记录，不脱敏展示给普通用户。

---

## 八、验收标准

- [ ] `hyzs_operation_logs` 表通过启动迁移自动创建。
- [ ] 在台账人工点 V/X/0、清除标记，`/logs` 可见对应审计记录（含前后值）。
- [ ] 批量导入、批次推送 OA、删除行动项各有记录。
- [ ] 会议创建/锁定/删除/生成纪要各有记录。
- [ ] `/logs` 支持按操作人、动作、时间筛选，分页正常。
- [ ] 写入失败不影响原操作（模拟 DB 断开时主流程仍成功）。
- [ ] 普通用户看不到 `/logs` 入口与接口数据。
