# 周例会看板（/weekly-board）需求文档

> 版本：v1.1  ·  状态：已上线（首页 + 明细页 + 占位插槽）
> 负责人：前端  ·  关联接口：`GET /api/actions`

---

## 1. 背景

周例会产出大量行动项（提议内容、节点、部门、责任人），目前散落在「行动项台账」表格中，不便在例会现场/汇报场景下快速翻阅。需要一个**演示型看板**，按页滑动浏览，便于投屏与逐项过会。

## 2. 目标

- 提供一个独立路由 `/weekly-board`，以**幻灯片（PPT）**形式呈现周例会待办。
- 第 1 页为统计汇总，后续为异构内容页（每页主题不同，可后续追加）。
- 支持滑动、键盘翻页、沉浸全屏、自动播放，适配投屏汇报。
- 不改动台账数据，为**只读演示 + 轻交互**。

## 3. 用户故事

| 角色 | 故事 |
|------|------|
| 管理者 | 我想在周例会上投屏，一页看到本期待办全貌（总数/部门分布/优先级），再逐页翻看明细。 |
| 管理者 | 我想用键盘 ←/→ 翻页，避免离开电脑操作鼠标。 |
| 秘书 | 我想从「行动项台账」一键跳到演示页，准备汇报。 |

## 4. 功能范围

### 4.1 包含
- 横向滑动幻灯片框架（Embla），16:9 卡片视觉。
- 第 1 页 **统计汇总**：待办/已处理/本周到期/已超期 四张数字卡 + 部门分布条形图 + 优先级环图。
- 第 2 页 **待办明细看板**：四字段卡片（提议内容 / 节点 / 部门 / 责任人），未处理项，按优先级色点区分。
- 占位页（后续异构内容插槽）。
- 控制栏：刷新、自动播放（6s/页）、沉浸模式。
- 键盘控制：←/→ 翻页、F 切全屏、Esc 退出全屏。
- 底部页码 + 圆点导航。

### 4.2 不包含（本期）
- 在演示页内修改行动项状态（轻交互仅限翻页/全屏/播放）。
- 导出为 PPT 文件。
- 多套主题/换肤。
- 服务端渲染数据（前端拉取 `/api/actions`）。

## 5. 数据来源

复用 `GET /api/actions`，取以下字段：

| 字段 | 用途 |
|------|------|
| `description` | 提议内容 |
| `due_date` / `due_date_type` | 节点（日期 / 持续跟进 / 未定） |
| `dept` | 部门 |
| `owner` | 责任人 |
| `proposer` | 提议人（预留） |
| `priority` | 优先级（high/medium/low） |
| `status` | 状态（映射为 未处理/已处理/已取消） |

> 不新增接口，不改动返回结构。

## 6. 页面结构

```
┌─ 顶部工具栏：当前页标签 | 刷新 · 自动播放 · 沉浸 ─┐
│                                                  │
│            [幻灯片区，16:9，可滑动]                │
│   ← 左翻页                            右翻页 →   │
│                                                  │
└─ 底部：页码 N/M + 圆点导航 ──────────────────────┘
```

### 6.1 第 1 页 统计汇总
- 四张数字卡：待办（未处理）/ 已处理 / 本周到期 / 已超期。
- 部门分布：横向条形图（未处理项，取前 6 部门）。
- 优先级分布：三环图（紧急/正常/宽松，未处理项）。

### 6.2 第 2 页 待办明细
- 卡片网格（2~3 列），每张卡片：
  - 优先级色点 + 提议内容（最多 2 行）。
  - 三个标签：部门、节点（日期/持续/超期红色）、责任人。
- 仅展示**未处理**项。

### 6.3 占位页
- 灰色占位，提示后续内容待定义。

## 7. 交互需求

| 操作 | 行为 |
|------|------|
| 鼠标拖拽 / 触屏滑动 | 切换上一页/下一页 |
| 键盘 → / ← | 下一页 / 上一页 |
| 键盘 F | 切换沉浸全屏 |
| 键盘 Esc | 退出沉浸全屏 |
| 点击底部圆点 | 跳到对应页 |
| 自动播放按钮 | 每 6 秒翻页，末页回到首页循环 |
| 刷新按钮 | 重新拉取 `/api/actions` |

## 8. 入口与权限

| 入口 | 位置 | 角色 |
|------|------|------|
| 侧边栏「业务协同 → 周例会看板」 | dashboard-layout | admin / manager / secretary |
| 行动项台账顶部「演示」按钮 | `/tracking` | 所有可见台账的角色 |

> 权限沿用 `/api/actions` 的会议可见性过滤，不在前端额外做。

## 9. 非功能需求

- **性能**：首屏拉取一次 `/api/actions`，前端计算统计，无轮询。
- **兼容**：Chrome/Edge 现代版，支持投屏 1920×1080。
- **Hydration**：所有动态内容客户端挂载后渲染，避免 SSR 不一致。
- **无障碍**：翻页按钮带 aria-label，键盘可达。

## 10. 验收标准

- [ ] 侧边栏与台账页两个入口均可进入 `/weekly-board`。
- [ ] 第 1 页四个统计数字与台账过滤结果一致。
- [ ] 第 2 页卡片展示提议内容/节点/部门/责任人四字段。
- [ ] ←/→、F、Esc 键盘控制生效。
- [ ] 沉浸模式覆盖全屏，圆点导航可跳页。
- [ ] 无数据时各页有空状态提示。

## 11. v1.1 统计周期口径（2026-08-31，行动项与持续项分离）

### 11.1 背景

原实现里行动项数据周与持续项填报统计共用同一周期（`dataPeriod`），导致两个问题：
1. 周期锚点曾绑定「最近一次实际周例会」，纪要未上传时看板停留在两周前的数据（v1.1 已改为锚定今天）；
2. 持续项的"本期填报"统计口径与业务不符——填报是**两次例会之间**的行为，不是自然周概念。

### 11.2 口径定义（两种周期相互独立）

| 周期 | 口径 | 示例（今天 8/31 周一） |
|------|------|----------------------|
| **行动项数据周** | 锚定「今天」，永远显示今天的**上一自然周**（周一~周日）；与会议纪要上传与否无关；‹/› 可翻历史周 | 8/24~8/30 |
| **持续项填报窗口** | **上次周例会次日 ~ 本次会议日**。周例会固定周一召开 ⇒ 等价于"数据周整体后移一天"（周二~周一） | 8/25~8/31 |

- 持续项"本期填报/未填报"按**填报窗口**统计（窗口内取最新一条填报记录）；
- 行动项完成率、到期、未完成通报按**数据周**统计；
- 界面需明示两个窗口：持续项汇报页副标题 + 总览页持续项标题均显示填报窗口日期。

### 11.3 前提与已知限制

- **前提：周例会固定周一召开**（当前业务事实）。
- 若将来例会日调整（如改周二），"数据周+1天"的等价关系失效，需将填报窗口改为按真实会议记录动态计算（上次会次日~本次会日），此为预留的 v2 扩展点。
- 翻历史周（‹）时，填报窗口随数据周同步整体前移 7 天。

### 11.4 验收标准（v1.1 追加）

- [ ] 今天为周一 8/31 时，看板标题显示 W35，行动项数据周为 8/24~8/30。
- [ ] 持续项汇报页副标题显示填报窗口「8/25~8/31」。
- [ ] 8/25~8/31 之间有填报记录的持续项显示填报内容；仅 8/24（含）之前填报的显示"未填报"。
- [ ] 总览页持续项统计卡"已填报/未填报"按 8/25~8/31 窗口计数。
- [ ] 8.24（周一）当天上传会议纪要与否，不影响两个周期的显示。
