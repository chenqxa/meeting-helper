# 会议助手系统 功能需求总册

> 版本：v1.0 · 日期：2026-08-28 · 状态：已评审（口径部分经业务确认定稿）
> 说明：本文档为系统全量功能需求基线，覆盖当前所有功能模块及统一业务口径；后续新功能按 `docs/feature/<功能名>/` 三件套追加，本文档同步更新索引。

---

## 一、系统概述

### 1.1 定位

以**会议**为核心的任务闭环系统：开会记录 → AI 生成纪要/行动项 → 归档推送 OA → 待办跟进 → 完成回传稽核 → 周期汇报（周例会/月度/产销会）。打通 OA（泛微）、企业微信、IM 三条通道。

### 1.2 角色与权限

| 角色 | 说明 | 主要能力 |
|------|------|---------|
| admin | 系统管理员 | 全部功能；群体项代填；稽核打分（V/X/0）；推送配置 |
| manager | 管理层 | 查看全部任务/看板/台账；稽核打分 |
| secretary | 秘书 | 创建会议、锁定归档、查看全部任务 |
| employee | 普通员工 | 我的任务、我的会议、汇报进展、提出反馈 |

角色来源：`hyzs_user_roles` 表，兜底环境变量 `DEFAULT_ADMIN_LOGINIDS` 等。

## 二、功能模块需求

### 2.1 工作台（/）

- 个人待办统计、快捷入口、最近会议。
- **待办角标统计范围**：仅统计「**责任人 = 当前用户**」的行动项（数据源 `/api/actions/mine`，按姓名/loginid/OA id 三重匹配）；**不含**"提出人待回执"数量（提出人回执走企微完成通知，不进角标）；群体项不计入（角标请求未开群体开关）。
- **排除项**：已处理（done）、已勾稽（verified）、已取消、已打稽核标记（V/X/0）。
- **持续项**：本周期已填报 → 不计入角标。⚠️ 现状：角标的周期起点用的是"距最近周五（推送日）"，与 3.2 定稿分界线（会议记录创建时刻）不同源，待统一（见遗留 #6）。

### 2.2 待办中心（/kanban）⭐核心

三种视图 + 两种展现形态（看板/日历）：

| 视图 | 可见角色 | 内容 |
|------|---------|------|
| 👁 全部任务 | admin/manager/secretary | 全部已归档会议 + 批次任务；可拖拽、编辑（管理角色） |
| 👤 我的任务 | 全员 | 责任人=我的卡片；汇报进展弹窗（文字+状态+截图粘贴） |
| 👥 群体项 | admin/manager | 责任人为群体的持续项；卡片带「代填汇报」按钮与最近填报展示 |

**日历形态**（与看板共用 filteredCards，切换按钮在筛选行右侧）：

- **挂载规则**：行动项按 `due_date` 挂到对应日期格子；**无截止日期的项不进日历** → 🔄持续项、❓待定项在日历中不出现。
- **群体项**：群体项均为持续项（无截止日）→ **群体项视图 + 日历形态 = 空白页**（属已知限制，如需支持再立项）。
- **逾期标识**：日期已过且状态非 done/blocked 的项显示为**红色胶囊**；正常待办为绿色胶囊；已完成为灰色胶囊；每格最多展示 3 条（超期 2 + 正常 2 优先），超出显示"+N"，点击日期格在右侧面板查看当日全部。
- 今日高亮蓝色圆点；月份可翻页。

规则：
- **持续项卡片显隐**：在填报周期内且本周期未填报 → 显示"本期待填报"；已填报/已翻篇 → 消失（详见 3.2）。
- **列归类**：打 V/done → 已处理；打 X/0 → 不进待办；持续项本周期已填 → 视作已处理。
- **逾期列**：仅日期型节点参与逾期判定。
- 企微卡片入口：`?view=my&shared=true&meetingId=xx`（归档卡片聚焦）或 `?type=continuous&pushId=xx`（持续项推送批次精确过滤）。
- 群体判定：统一使用 `isGroupOwner` 名单（所有人/各部门/各部门负责人/品质部/采购部… + "全体/所有/各"前缀模式）。

### 2.3 我的任务（/mytasks）

- 当前用户名下全部行动项（仅**已归档会议**来源），按状态分组（未处理/已处理/已取消）。
- 汇报两选一：已完成（V）/ 未完成（X + 下次完成时间自动重派新任务）。
- 持续项周期汇报：进展写入周期进展表，"无进展"为合法状态。
- 👥群体项开关（admin/manager）：附带群体责任人持续项，代填模式。
- 图片证据：弹窗内 Ctrl+V 粘贴截图，必填（持续项除外）。

### 2.4 会议中心（/meetings、/meeting/[id]）⭐核心

**流程**：创建会议（文本/录音转写）→ AI 生成纪要（多模型可选）→ 摘要/行动项派生 → 行内编辑确认 → 锁定归档（推送 OA + 企微卡片）→ 分享/导出。

- **会议创建**：标题、类型（周例会/周会/产销会/公司月会/其他）、日期、参会人、组织者；录音实时转写或粘贴文本。
- **纪要**：结构化编辑 + Markdown 正文双模式；行内编辑即时保存；外部数据变化不覆盖正在编辑的内容（dirty 保护）；多人并发保存冲突提示（409 确认后可覆盖）。
- **摘要**：从纪要自动派生，行内可编辑。
- **行动项**：行内编辑（描述/提出人/负责人/节点类型/日期/优先级），像填 Excel 一样连续录入，不跳焦不丢数据；新增/复制/删除；节点类型三态（📅日期 / 🔄持续 / ❓待定）。
- **数据一致性规则**（2026-08-28 修复定稿）：
  - 手动新增/编辑过的行动项**永不因保存纪要被删除**；仅"纯派生且零手动编辑"的项随纪要表格删行软取消（台账留痕）。
  - **"手动编辑过"的判定方式**：**不是存储标记，而是保存纪要时服务端的字段值启发式判定**（不新增字段、无需迁移）——满足任一条件即视为手动维护：
    1. id 不属于派生模式（派生项 id 固定为 `action-N`；手动新增项为 `new-*`/`rd-*` 等）；
    2. 任一"手动字段"有值：责任人/提出人（姓名、loginid、OA id、部门）、截止日期、优先级≠中、状态≠待处理、OA 回传结果/稽核分、确认人、完成人、阻塞原因等。
    - 已知近似性：若手动填入的值恰好等于派生默认值（如手动填了与表格相同的负责人），仍会被判为"未动"，表格删行时会联动取消——极端场景，接受。
  - 派生匹配：描述优先 → id 精确；派生值不覆盖手动字段（提出人/优先级/节点类型/状态/OA 回传）。
  - 台账（SQL Server）为主数据源，会议 JSON 并集合并；新增先写台账（幂等防重复）；历史"仅在 JSON"的项可见、首次编辑自动回填。
  - 行动项 id 会话期内稳定（行不重挂载、焦点不丢）。
- **归档（锁定版本）**：校验低置信度项已确认 → 锁定 → 推送 OA 待办 + 企微卡片 + IM；已归档会议可继续补项（自动补推 OA）；解除归档保留 OA 数据与台账。
- **分享**：参会人外可通过分享链接（企微 OAuth 免密）查看/填写。
- **导出**：Word/PDF 会议纪要。

### 2.5 周例会看板（/weekly-board）⭐演示

投屏演示页（15:9 幻灯片滑动）：
1. **未完成项通报**：数据周期内节点到期未完成项 + 完成率统计栏。
2. **持续项跟进**：已完成/未完成两页。
- 统计周期口径见 3.1；完成率口径见 3.4。

### 2.6 月度看板（/monthly-board）/ 产销会看板（/production-board）

与周例会看板同引擎，按月度/产销会类型聚合；产销会/公司月会填报归属"数据月"（见 3.3）。

### 2.7 行动项台账（/tracking）

全量行动项管理表：筛选（会议/责任人/部门/状态/周次）、稽核打分（V/X/0）、CSV 导出；W 徽标按会议日期 ISO 周号；未打分但超期且无回传 → 自动 X。

### 2.8 持续项跟进（/continuous）

持续项全生命周期视图：按会议类型/周次分组、推送台账（每期推送/已填/未填）、填报内容与附件查看、手动推送（admin）。

### 2.9 贡献看板（/contribution）

个人贡献统计（周榜/月榜），排除群体/部门责任人；口径与台账一致。

### 2.10 反馈台账（/feedback）

用户反馈收集与处理状态管理。

### 2.11 批次管理（/batches、/batch/[id]）

Excel 批量导入行动项（含持续项），推送 OA/企微，批次状态跟踪（草稿/已推送/作废）。

### 2.12 项目协同（/projects、/project/[id]）

项目维度的需求/任务/风险聚合（当前导航隐藏，按需开启）。

### 2.13 系统管理

- **组织（/org）**：OA 组织同步、人员列表（凌晨 02:00 自动同步）。
- **基础设置（/settings）**：角色权限配置。
- **OA 同步（/oa-sync）**：OA 回拉（完成情况/附件回传→台账稽核字段）。
- **操作日志（/logs）**：全部关键操作留痕（登录/汇报/稽核/推送/删除等），仅 chenqiaoxia 可见。

### 2.14 推送体系（后台调度）

| 推送 | 时机 | 对象 | 规则 |
|------|------|------|------|
| 每日待办 | 每日 09:00 / 17:30 | 个人 | 已归档会议 + 活跃状态（pending/confirmed/in_progress/blocked/candidate）行动项，按人聚合 |
| 持续项打包 | 配置驱动（周例会=每周五 09:00） | 责任人 | 未打稽核标记 + **本周期未填报**才推；**群体责任人项不推**（只在系统内群体项视图代填）；OA 待办 + IM + 企微汇总卡片（带批次，点击直达精确列表） |
| 归档推送 | 锁定版本时 | 责任人/提出人 | OA 待办 + 企微卡片（按人聚合，内容无变化不重发）|
| 新增补推 | 已归档会议补项时 | 新项责任人 | 自动补推 OA |
| 完成闭环通知 | 标记已完成时 | 提出人 | 企微卡片回执；群体提出人不发；自己提自己做不发 |

## 三、统一业务口径（2026-08-28 业务确认定稿）⭐

### 3.1 周号与周例会统计周期

- **周号**：ISO 标准周号（周一为一周起点）。经核对与公司周历一致（8/3=32周 → 8/24=35周 → 8/31=36周）。
- **周例会数据周期**：**自然周**——8/24（周一）开会汇报 **8/17~8/23**（上周一~上周日）。标题"开会周 N = 数据周 N-1"。锚定最近一次实际周例会，停开会周期不乱。
- **完成率**（见 3.4）与此周期同源。

### 3.2 持续项"新一周"分界线

**分界线 = 该类型最近一次周例会的「会议记录创建时刻」（≈开完会、传完纪要）**：

- 分界线**之前**填报 → 算当周（上一周期），周五催办还会催；
- 分界线**之后**填报 → 算新一周，本期推送跳过；
- 看板"本期待填报"卡片自分界线起显示；
- 无创建时间的历史会议回退"会议次日"；查不到会议记录回退"最近自然周一"。

三条链路（看板显隐、已填报判定、推送跳过）**同一条分界线**。

### 3.3 月度会议（产销会/公司月会）归属

填报归属"**最近一次已开完同类会议所在月份**"（data_month）：8 月开的产销会看 7 月数据 → 8/17 填报写入 data_month=2026-07。

### 3.4 周例会完成率统计范围

只统计：会议类型 ∈ {周会、周例会} 且**有明确截止日期**的行动项；🔄持续项、❓待定项**不计入**；打 0 分（待定）不计入分母；已取消不计入。

### 3.5 群体项

- 判定统一 `isGroupOwner`（所有人/各部门/各部门负责人/全体成员/品质部/采购部/…及"全体/所有/各"前缀模式）。
- **不参与任何推送**（OA/IM/企微均无具体接收人）。
- 仅出现在：待办中心「👥群体项」视图 + 我的任务群体项开关（admin/manager），由管理员**代填汇报**。
- 贡献统计排除群体项。

### 3.6 待办可见性

- 未归档会议的行动项**不进**个人待办/推送（先确认再进入流转）。
- 打过稽核标记（V/X/0）的项不再是待办。
- 已删除行动项软删除（status=cancelled，台账留痕），不物理删除。

## 四、数据与存储

| 数据源 | 用途 |
|--------|------|
| `hyzs_meetings`（会议 JSON：纪要/摘要/行动项快照） | 会议详情页展示 |
| `hyzs_action_items`（行动项台账，**主数据源**） | 待办/台账/推送/OA 回传 |
| `hyzs_continuous_progress`（周期填报） | 持续项每期进展 |
| `hyzs_push_batches`（推送批次） | 企微卡片精确回链 |
| OA `uf_meetingplan`（链接服务器） | OA 待办下发与回拉 |
| 企微通讯录 | 用户匹配、卡片推送 |

双源规则：台账优先，会议 JSON 并集补充；写路径先台账后 JSON，失败降级告警不丢数。

## 五、非功能需求

- **性能**：100+ 行动项、万字纪要下编辑响应 ≤100ms；远程库列表查询有 15 秒缓存（写操作后失效）。
- **一致性**：行动项三处（JSON/台账/前端）id 与字段一致；删除全部留痕可追溯。
- **安全**：SSO/企微 OAuth 登录；会议仅参会人/主持人可见；接口按角色守卫；分享链接走 OAuth + 参与人校验。
- **可用性**：行动项/纪要编辑不跳焦、不丢字（2026-08-28 修复基线）。
